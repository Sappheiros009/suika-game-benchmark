# 수박게임 구현 과제

제공된 과일 리소스와 코드 템플릿을 이용해 수박게임을 만듭니다. 코드를 채우는 것뿐 아니라 씬, Prefab Variant, Animator, UI를 직접 구성하고 연결하는 것이 목표입니다.

> **과제 안내 초안**: 현재 합의된 게임 동작과 템플릿 범위를 바탕으로 작성했습니다. 아래 배점·통과 점수·대체과제 추가 기능·제출 형식은 검토를 위한 제안이며, 확정된 공지가 아닙니다.

## 1. 진행 방식

- Unity 버전: `6000.6.7f1`
- 실습 브랜치: `assignment-template`
- 입력 방식: 구버전 Input Manager. Active Input Handling을 `Input Manager (Old)`로 설정합니다. 입력 방식 변경 후에는 에디터를 재시작합니다.
- UI 글자는 TextMeshProUGUI를 사용합니다.
- 과일 단계: **체리 → 귤 → 사과 → 멜론 → 수박**
- 플레이 중 무작위로 떨어뜨릴 수 있는 과일은 **체리·귤·사과**입니다. 멜론과 수박은 합체로만 만듭니다.
- 수박이 마지막 단계입니다. 수박 두 개가 만나도 추가 합체하지 않습니다.

### 제공 코드와 직접 구현할 부분

| 구분 | 제공 내용 | 학생 작업 |
| --- | --- | --- |
| `FruitDropManager` | 초기 참조 확인, 낙하 간격 검사, 위치 제한 계산 등 | 입력, 낙하, 다음 과일 선택, 위치 이동, 라운드 초기화 |
| `FruitMerge` | 합체 조건 검사, 대기 시간 계산·적용, Scene 이동, 물리 활성화 | 충돌 콜백, 합체 상태 변경, 과일 교체, 속도 전달, 점수 요청 |
| `GameOverManager` | `FixedUpdate`의 높이·시간 판정 전체, 시간 정지·복원 | 재시작 입력, 게임오버 전환, 과일 제거와 초기화 |
| `ScoreManager` | 완성 코드 | 컴포넌트와 TMP 참조 연결, 제공 메서드 호출 |
| `FruitContactExpression` | 완성 코드 | 공통 과일 프리팹과 Animator 참조 연결 |

`ScoreManager`의 싱글톤이나 `FruitContactExpression`의 Animator 값 전달 코드는 직접 작성하지 않아도 됩니다. 두 스크립트는 완성 상태로 사용합니다. 다만 Inspector 참조와 Animator 상태 전환은 직접 설정합니다.

코드 안의 TODO와 주석 예시를 참고하세요. `GameObject fruit = null`, `GameObject merged = null`은 미완성 템플릿의 컴파일을 위한 임시 값입니다. 실제 생성한 오브젝트를 해당 변수에 대입해야 합니다. TODO 한 곳을 완성했다고 기능 전체가 완성되는 것은 아닙니다. 생성 후 다음 과일 선택, 이동 후 위치 보정, 게임오버 상태 변경처럼 메서드 사이의 연결도 확인하세요.

과제 브랜치에는 정답 씬(`SuikaGame`)과 에디터 자동 구성 도구를 포함하지 않습니다. `SampleScene`을 바탕으로 평가용 씬을 직접 구성하고 제출할 씬 경로를 명시하세요. 정답 씬과 자동 구성 도구는 강사용 `main` 브랜치에 보존합니다.

### 안내선 스프라이트 배치

`Assets/Art/Guides`의 두 PNG는 투명 배경이며 Sprite (Single), Pixels Per Unit 200으로 설정되어 있습니다. 각 이미지를 Hierarchy 또는 Scene에 드래그하면 SpriteRenderer 하나로 사용할 수 있습니다. Collider나 Rigidbody2D는 추가하지 않습니다.

| 이미지 | 오브젝트 이름 | 배치 예시 | 연결 대상 |
| --- | --- | --- | --- |
| `drop_guide.png` | `DropGuide` | 세로 점선의 중심 `(0, 0.805, 0)`, Scale `(1, 1, 1)` | FruitDropManager와 GameOverManager의 Drop Guide |
| `game_over_line.png` | `GameOverLine` | 가로 파선의 중심 `(0, 1.45, 0)`, Scale `(1, 1, 1)` | GameOverManager의 Height Limit |

위 좌표는 바구니 중심 x=0, DropPoint y=2.4인 기존 배치 기준의 예시입니다. 직접 만든 바구니 크기에 맞게 위치와 크기를 조정해도 됩니다. GameOverLine의 Transform y가 실제 게임오버 판정 높이이므로 이미지 중앙과 판정선을 일치시키세요. DropGuide는 과일 부모가 아닌 플레이필드 아래에 두고 이동 시 x만 바꿉니다. 이미지 전체의 높이를 기준으로 배치하므로 점선을 여러 자식 오브젝트로 만들 필요가 없습니다.

URP 2D에서 그림이 어둡게 보이면 SpriteRenderer에 제공 `Assets/Art/Layout/SpriteUnlit.mat`을 연결하세요. Sorting Order 예시는 DropGuide=-1, GameOverLine=2, 과일 Body=5입니다.

## 2. 평가와 통과 기준 제안

아래 점수는 게임 안에서 얻는 점수와 별개인 **과제 평가 점수**입니다.

| 구분 | 총점 | 통과 기준 제안 |
| --- | ---: | --- |
| 최종과제 | 100점 | 기본 항목 합계 70점 이상 |
| 대체과제 | 130점 | 기본 항목과 추가 항목 합계 100점 이상, 추가 항목에서 10점 이상 |

모든 기능을 구현해야 통과하는 방식이 아닙니다. 각 세부 조건에 적힌 점수를 합산합니다. 대체과제는 최종과제와 같은 기본 항목에 추가 기능을 더하며, 추가 기능 세 가지를 전부 구현할 필요는 없습니다. 예를 들어 기본 90점 + 추가 10점, 또는 기본 80점 + 추가 20점이면 대체과제 통과 기준에 도달합니다.

컴파일되고 평가용 씬을 실행할 수 있는 상태로 제출하세요. 미완성 기능이 있어도 확인 가능한 세부 조건은 채점합니다. 한 기능의 실패만으로 다른 항목까지 일괄 0점 처리하지 않습니다. 무작위 생성에 의존하지 않고 검증할 수 있도록 별도 테스트 씬에서 과일을 미리 배치해도 됩니다.

| 번호 | 기본 평가 항목 | 배점 |
| --- | --- | ---: |
| 1 | 씬과 바구니 구성 | 10점 |
| 2 | 공통 과일 프리팹과 Variant | 10점 |
| 3 | 표정 Animator 구성 | 10점 |
| 4 | 키보드 이동과 과일 낙하 | 15점 |
| 5 | 다음 과일 선택과 UI | 10점 |
| 6 | 같은 과일 합체 | 20점 |
| 7 | 점수 연결 | 10점 |
| 8 | 게임오버와 재시작 | 15점 |
| | **기본 항목 합계** | **100점** |

## 3. 공통 평가 항목 — 최종과제·대체과제 모두 해당

### 1) 씬과 바구니 구성 — 10점

- **화면 구성 3점**: 카메라에서 바구니, 낙하 위치, 제한선, 현재·최고 점수, 다음 과일 UI를 볼 수 있습니다. 글자와 이미지가 잘리거나 서로 가려지지 않게 배치합니다. 화면 배치·색·장식은 자유롭게 정해도 됩니다.
- **바구니 충돌 영역 4점**: 제공 바구니 스프라이트를 배치하고 좌우 벽과 바닥에 Collider를 구성합니다. 과일이 안쪽에 쌓이고 벽이나 바닥을 통과하지 않아야 합니다. 그림과 충돌 영역의 위치를 맞춥니다.
- **매니저와 참조 연결 3점**: 매니저 객체에 `FruitDropManager`, `GameOverManager`, `ScoreManager`를 붙입니다. 낙하 위치, 생성 과일 부모, 벽, 제한선, 가이드, UI 등 각 컴포넌트의 참조를 연결합니다. 생성 과일은 게임오버 매니저가 확인하는 부모 아래에 모여야 합니다.

### 2) 공통 과일 프리팹과 Variant — 10점

- **공통 베이스 4점**: `FruitBase` 루트에 Rigidbody2D, CircleCollider2D, `FruitMerge`, `FruitContactExpression`을 구성합니다. 자식 `Body`에는 몸통 SpriteRenderer, `Face`에는 표정 SpriteRenderer와 Animator를 둡니다. 표정은 몸통 앞에 보이게 정렬합니다.
- **5종 Variant 4점**: 공통 베이스를 상속하는 체리·귤·사과·멜론·수박을 만듭니다. 각 Variant의 몸통 이미지, 크기, Fruit Type, Next Fruit Prefab을 연결합니다. 다음 프리팹 순서는 체리→귤→사과→멜론→수박이며 수박의 다음 프리팹은 비웁니다.
- **물리 설정 2점**: 과일은 Dynamic Rigidbody2D와 Trigger가 아닌 Collider를 사용합니다. 베이스의 Sleeping Mode를 `Never Sleep`으로 설정하고 Variant가 상속하도록 합니다. 몸통 크기와 Collider 크기를 맞추고 생성 시 중력으로 떨어지는지 확인합니다.

### 3) 표정 Animator 구성 — 10점

- **클립과 공통 Controller 4점**: 기본 표정 Idle과 찡그린 표정 Contact를 구성합니다. 각 클립에서 `Face`의 스프라이트를 바꾸고 기본 상태는 Idle로 설정합니다. 공통 Controller는 베이스의 Face에 연결하며 과일마다 별도 Controller를 만들지 않습니다.
- **상태 전환 3점**: Bool 파라미터 `IsTouching`을 정확한 이름으로 추가합니다. true일 때 Contact, false일 때 Idle로 이동하도록 양방향 전환을 설정합니다. 전환이 애니메이션 종료를 기다리며 지연되지 않게 설정합니다.
- **접촉 동작 3점**: 다른 과일과 닿아 있을 때만 `>.<` 표정입니다. 벽·바닥만 닿을 때는 Idle입니다. 여러 과일과 닿았다가 하나만 떨어졌을 때는 Contact를 유지하고, 모든 과일 접촉이 사라지면 Idle로 돌아옵니다. 제공된 `FruitContactExpression`을 연결해 확인합니다.

### 4) 키보드 이동과 과일 낙하 — 15점

- **좌우 이동 4점**: ←/→ 또는 A/D를 누르고 있는 동안 DropPoint가 좌우로 움직입니다. 두 방향을 함께 누르면 이동하지 않습니다. `moveSpeed`와 `Time.deltaTime`을 반영하고 y·z 위치는 유지합니다.
- **위치 제한과 가이드 3점**: 이동 후 제공된 `ClampDropPosition`을 활용합니다. 현재 선택된 과일의 반지름을 고려해 양쪽 벽 밖으로 생성되지 않게 하고, 낙하 가이드도 DropPoint의 x 위치를 따르게 합니다.
- **과일 생성 5점**: Space를 누른 순간 현재 `NextFruitPrefab`을 DropPoint의 위치·회전으로 생성합니다. 지정한 과일 부모 아래에 넣고 물리 시뮬레이션을 켭니다. 반환값은 실제 생성한 오브젝트여야 합니다. 키를 계속 누르고 있어도 반복 생성하지 않습니다.
- **낙하 간격과 진행 상태 3점**: 기본 0.4초 낙하 간격을 유지합니다. 간격 안에 다시 눌러도 추가 생성하지 않으며 게임오버 중에는 이동·낙하하지 않습니다. Inspector의 Drop Cooldown을 바꾸면 간격도 바뀌어야 합니다.

### 5) 다음 과일 선택과 UI — 10점

- **무작위 선택 4점**: 프리팹 배열에 체리·귤·사과만 넣고 배열 범위 안에서 무작위 선택합니다. 시작할 때 한 번 선택하며, 낙하를 성공할 때마다 다음 과일을 다시 선택합니다. 같은 과일이 연속 선택되어도 정상입니다. 멜론·수박은 낙하 대상으로 나오지 않아야 합니다.
- **다음 과일 표시 4점**: UI 이미지에는 선택된 프리팹의 Body 스프라이트를, 이름에는 해당 과일 이름을 표시합니다. 화면에 표시된 과일과 다음 Space 입력으로 실제 생성되는 과일이 일치해야 합니다. 선택이 바뀌면 이미지와 이름을 함께 갱신합니다.
- **선택 변경 후 보정 2점**: 다음 과일의 크기가 바뀌어도 벽과 겹쳐 생성되지 않도록 낙하 위치를 다시 보정합니다. 특히 가장자리에서 체리 다음에 사과가 선택되는 경우를 확인합니다.

### 6) 같은 과일 합체 — 20점

- **충돌 연결 4점**: `OnCollisionEnter2D`와 `OnCollisionStay2D`에서 상대 과일의 `FruitMerge`를 찾아 합체를 시도합니다. 같은 종류일 때만 합체하며, 서로 다른 과일이나 벽·바닥과 닿았을 때는 합체하지 않습니다. 제공 조건 검사를 활용합니다.
- **다음 단계 생성 6점**: 두 과일을 소비하고 다음 단계 하나를 두 위치의 중간에 생성합니다. 새 과일은 기존 과일의 부모 아래에 두며, 원본 두 개는 비활성화 후 제거합니다. 체리 두 개→귤, 귤 두 개→사과, 사과 두 개→멜론, 멜론 두 개→수박의 모든 단계를 확인합니다. 각 단계 성공마다 1.5점입니다.
- **중복 합체 방지 4점**: 생성·제거 전에 자신과 상대의 `IsMerging`을 먼저 설정합니다. 같은 두 과일의 충돌 콜백이 양쪽에서 실행돼도 결과가 두 개 생기지 않아야 합니다. 세 과일이 동시에 닿아도 하나의 과일이 두 번 소비되지 않아야 합니다.
- **연쇄 합체 대기 3점**: 합체 결과는 기본 0.2초 동안 다시 합체하지 않습니다. 예를 들어 체리 합체로 생긴 귤이 기존 귤과 닿으면 잠시 후 사과가 됩니다. 대기 후에도 계속 닿아 있다면 합체해야 하며, 떨어져 있으면 합체하지 않습니다. 일반 낙하 과일에는 이 생성 대기를 새로 적용하지 않습니다. 제공된 시간 처리와 Stay 콜백을 연결합니다.
- **물리와 마지막 단계 3점**: 원본 두 과일의 평균 선속도·평균 각속도를 결과에 전달합니다(2점). 수박은 추가 합체하지 않고 유지합니다(1점).

### 7) 점수 연결 — 10점

제공 `ScoreManager`를 사용합니다. 점수 로직·싱글톤을 새로 작성하거나 PlayerPrefs로 저장하는 작업은 요구하지 않습니다. 단순 낙하에는 점수를 주지 않고, 실제 합체 결과에 따라 아래 점수를 **누적**합니다.

| 생성된 합체 결과 | 게임 내 획득 점수 |
| --- | ---: |
| 귤 | 10점 |
| 사과 | 30점 |
| 멜론 | 80점 |
| 수박 | 200점 |

- **합체 보상 5점**: 합체 성공 시 생성된 과일의 Type으로 `AddMergeScore`를 한 번만 호출합니다. 원본 두 개 각각에 점수를 주거나 충돌 중 반복 가산하지 않습니다. 체리 두 개가 귤이 된 뒤 그 귤이 기존 귤과 합쳐지면 총 40점입니다.
- **점수 UI 3점**: 현재·최고·결과 점수 TMP를 연결합니다. 게임오버 패널에는 종료 시 현재 점수가 표시됩니다. 제공 표시 형식은 네 자리 숫자입니다.
- **라운드 연결 2점**: 게임오버 때 `FinishRound`, 재시작 때 `ResetScore`를 호출합니다. 재시작 시 현재 점수는 0, 최고 점수는 유지합니다. 최고 점수는 같은 ScoreManager가 살아 있는 동안만 유지되면 됩니다. 에디터 실행을 종료한 뒤까지 저장할 필요는 없습니다.

### 8) 게임오버와 재시작 — 15점

높이·시간 계산은 `GameOverManager.FixedUpdate`에 제공되어 있습니다. Dictionary나 접촉 판정 코드를 새로 작성할 필요 없이 참조 연결과 상태 전환을 구현합니다.

- **판정 설정 3점**: 제한선과 생성 과일 부모를 연결하고 생성 유예 시간 1초, 초과 허용 시간 1초를 설정합니다. 새로 추적된 과일은 유예 시간 동안 제외됩니다. 유예가 끝난 뒤 Collider 윗면이 제한선 위에 1초 연속 머물면 게임오버입니다. 순간적으로 넘었다 내려오면 초과 시간이 초기화됩니다. 과일 중심이 아닌 윗면을 기준으로 확인합니다.
- **게임오버 전환 5점**: `IsGameOver`를 설정하고 중복 처리를 막습니다. 낙하 매니저와 가이드를 끄고 결과 패널을 켭니다. 제공 시간 코드를 이용해 물리 진행을 멈추며, ScoreManager에 라운드 종료를 알립니다. 생성 직후 제한선을 잠깐 지나가는 것만으로 종료하면 안 됩니다.
- **재시작 입력 2점**: 게임오버 상태에서 R을 누른 순간에만 `RestartGame`을 호출합니다. 진행 중 R을 눌러도 현재 판을 초기화하지 않습니다.
- **재시작 초기화 5점**: 생성된 과일을 모두 비활성화 후 제거합니다. 과일 추적용 `states`, `fruits`, `removedFruits`를 비우고 게임오버 상태를 해제합니다. 제공 코드로 시간을 복원하고 낙하 매니저·가이드를 켜며 결과 패널을 숨깁니다. `ResetRound`로 낙하 대기·초기 위치·다음 과일을 초기화하고 현재 점수를 0으로 만듭니다. 두 번째 판에서도 낙하·합체·게임오버가 정상 동작해야 합니다.

## 4. 대체과제 전용 추가 평가 항목 — 최대 30점

이 절은 **대체과제에만 해당**합니다. 최종과제의 총점과 통과 판정에는 포함하지 않습니다. 아래 세 항목은 아직 확정되지 않은 추가 기능 제안입니다. 대체과제에서는 공통 항목 100점과 추가 항목 30점을 합쳐 총 130점으로 채점하며, 기본 기능 점수를 이 항목에서 다시 주지 않습니다.

### A) 다음 과일을 낙하 위치에 미리보기 — 10점

기본 다음 과일 UI와 별개로, DropPoint 위치에 떨어질 과일의 모습을 미리 보여줍니다.

- 선택된 과일과 같은 몸통 이미지·크기를 표시합니다(4점).
- 좌우 이동과 무작위 선택 변경을 따라 미리보기가 갱신됩니다(3점).
- 미리보기는 물리 충돌·합체·점수·게임오버 판정에 참여하지 않으며, 게임오버 시 숨고 재시작 시 복원됩니다(3점).

### B) 상황별 효과음 — 10점

- 낙하 성공 때 효과음을 한 번 재생합니다. 입력만 했거나 쿨다운 때문에 생성에 실패하면 재생하지 않습니다(3점).
- 합체 성공 때 효과음을 한 번 재생합니다. 계속 접촉한다고 반복 재생하지 않습니다(4점).
- 게임오버 전환 때 효과음을 한 번 재생합니다. 시간 정지 상태에서도 들리고 재시작 후 다음 게임오버에서도 정상 재생됩니다(3점).

외부 음원을 사용할 경우 사용 가능한 리소스를 선택하고 출처·이용 조건을 제출 안내에 적습니다.

### C) 수박 달성 연출 — 10점

- 실제 합체로 수박이 생성됐을 때 달성 문구나 패널을 표시합니다(4점).
- 파티클 또는 애니메이션으로 수박 달성을 시각적으로 표현합니다. 원본 두 과일의 콜백으로 같은 달성이 중복 실행되지 않아야 합니다(3점).
- 연출 후 기본 게임을 계속할 수 있고 수박의 추가 합체는 발생하지 않습니다. 재시작 시 연출 상태가 정리되며 다음 판에서도 다시 달성할 수 있습니다(3점).

## 5. 제출 및 확인 방법 제안

Unity 프로젝트의 `Assets`, `Packages`, `ProjectSettings`와 사용한 리소스의 메타 파일을 포함해 제출합니다. `Library`, `Temp`, `Logs`는 제출하지 않습니다. 평가용 씬 경로, 구현한 평가 항목, 미구현 항목, 별도 확인 방법을 간단히 적습니다.

제출 전 다음 순서로 직접 플레이해보세요.

1. 씬을 실행해 현재 점수 0과 다음 과일 UI가 표시되는지 확인합니다.
2. 양쪽 끝까지 이동하고 크기가 다른 과일을 선택해도 바구니 안에서 생성되는지 확인합니다.
3. Space를 길게 누르거나 빠르게 반복 입력해 낙하 횟수와 간격을 확인합니다.
4. 같은 과일·다른 과일·벽 접촉을 나눠 확인합니다. 각 합체 단계와 점수도 확인합니다.
5. 서로 다른 과일을 맞닿게 배치해 표정이 바뀌고, 떨어지면 기본 표정으로 돌아오는지 확인합니다.
6. 테스트 씬에 귤 하나와 체리 두 개를 배치해 귤 생성 후 대기 시간을 거쳐 사과가 되는지 확인합니다.
7. 과일을 제한선 위에 쌓아 유예·초과 시간이 지난 뒤 게임오버가 되는지 확인합니다.
8. R로 재시작한 뒤 과일 제거, 현재 점수 초기화, 최고 점수 유지, 낙하 위치 복원을 확인합니다.
9. 다시 플레이해 두 번째 게임오버와 재시작도 확인합니다.
