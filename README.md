# 수박게임 구현 과제

이 과제는 AI를 활용해 제작되었습니다.

과일을 떨어뜨리고 같은 과일을 합쳐 수박을 만드는 게임을 구현합니다. 씬, Prefab Variant, Animator, UI를 구성하고 게임 동작을 연결하는 것이 목표입니다.

**제공된 코드 템플릿 사용은 선택 사항입니다.** 템플릿의 빈칸을 채우거나 직접 코드를 작성해도 됩니다. 템플릿 사용 여부와 관계없이 동일한 기능과 플레이 영상 기준으로 평가합니다.

> **검토용 초안**: 배점과 통과 점수는 검토용 제안입니다.

## 1. 진행 방식

- Unity 버전: `6000.6.7f1`
- 입력 설정: Active Input Handling은 `Both`입니다. 과제의 키보드 입력 코드는 `Input.GetKey`와 `Input.GetKeyDown`을 사용합니다.
- UI 글자는 TextMeshProUGUI를 사용합니다.
- 과일 단계: **체리 → 귤 → 사과 → 멜론 → 수박**
- 플레이 중 무작위로 떨어뜨릴 수 있는 과일은 **체리·귤·사과**입니다. 멜론과 수박은 합체로만 만듭니다.
- 수박이 마지막 단계입니다. 수박 두 개가 만나도 추가 합체하지 않습니다.

### 제공 코드와 직접 구현할 부분

| 구분 | 제공 내용 | 학생 작업 |
| --- | --- | --- |
| `FruitDropManager` | 초기 참조 확인, 낙하 간격 검사, 위치 제한 계산 등 | 입력, 낙하, 다음 과일 선택, 위치 이동, 라운드 초기화 |
| `FruitMerge` | 합체 조건 검사, 대기 시간 계산·적용, Scene 이동, 물리 활성화 | 충돌 콜백, 합체 상태 변경, 과일 교체, 속도 전달, 점수 요청 |
| `GameOverManager` | `FixedUpdate`의 높이·시간 판정 전체, 시간 정지·복원 | 재시작 입력, 게임오버 전환, 과일 제거와 초기화 |
| `ScoreManager` | 완성 코드 | 컴포넌트와 TMP 참조 연결, 제공 메서드 호출 |
| `FruitContactExpression` | 완성 코드 | 공통 과일 프리팹과 Animator 참조 연결 |

템플릿에서는 `ScoreManager`와 `FruitContactExpression`을 완성 코드로 제공합니다. Inspector 참조와 Animator 상태 전환은 직접 설정합니다.

템플릿을 사용하는 경우 코드의 TODO를 채우고 플레이 씬을 구성하세요. `fruit = null`, `merged = null`에는 실제 생성한 오브젝트를 대입해야 합니다. 과일 생성 후 다음 과일 선택, 이동 후 위치 보정, 게임오버 상태 변경까지 연결하세요.

## 2. 제공 리소스와 사용 방법

아래 리소스를 사용해 씬과 과일 프리팹을 구성합니다. 위치·크기·색은 화면에 맞게 조정해도 됩니다.

| 경로 | 내용 | 용도 |
| --- | --- | --- |
| `Assets/Art/Fruits/` | `cherry.png`, `mandarin.png`, `apple.png`, `melon.png`, `watermelon.png` | 각 과일의 `Body` SpriteRenderer |
| `Assets/Art/Faces/` | `face_idle.png`, `face_contact.png` | 공통 `Face`의 기본 표정과 접촉 표정 애니메이션 |
| `Assets/Art/Basket/basket_frame.png` | 안쪽이 투명한 바구니 테두리 | 바구니 SpriteRenderer |
| `Assets/Art/Guides/drop_guide.png` | 세로 점선 | 낙하 위치를 표시할 `DropGuide` |
| `Assets/Art/Guides/game_over_line.png` | 가로 파선 | 높이 제한을 표시할 `GameOverLine` |
| `Assets/Art/Layout/` | `Rounded.png`, `Circle.png`, `SpriteUnlit.mat` | 패널 장식과 스프라이트 표시용 머티리얼 |
| `Assets/TextMesh Pro/` | TMP 기본 리소스와 LiberationSans SDF 폰트 | 점수·과일 이름·안내 문구 |

### 과일·표정·바구니

- 몸통과 표정은 서로 다른 SpriteRenderer로 배치합니다. `Body`보다 `Face`가 앞에 보이도록 Sorting Order를 설정합니다. 과일별로 표정을 다시 그릴 필요 없이 공통 표정 이미지를 사용합니다.
- 바구니 이미지는 그림만 제공합니다. 좌우 벽과 바닥의 Collider를 별도로 구성하고 그림 안쪽 경계에 맞춥니다.
- 화면이 어둡게 보일 경우 SpriteRenderer에 제공 `SpriteUnlit.mat`을 연결할 수 있습니다.

### 낙하 가이드·게임오버 제한선

두 안내선 PNG는 투명 배경, Sprite (Single), Pixels Per Unit 200으로 설정되어 있습니다. 이미지를 Scene에 드래그하면 SpriteRenderer 하나로 사용할 수 있습니다. 두 안내선에 Collider나 Rigidbody2D를 추가하지 않습니다.

| 이미지 | 오브젝트 이름 | Inspector 연결 대상 |
| --- | --- | --- |
| `drop_guide.png` | `DropGuide` | FruitDropManager와 GameOverManager의 Drop Guide |
| `game_over_line.png` | `GameOverLine` | GameOverManager의 Height Limit |

안내선의 위치와 크기는 직접 구성한 바구니와 화면에 맞게 조정하세요.

- `DropGuide`는 생성 과일 부모 밖에 두고, DropPoint를 따라 x 좌표만 이동시킵니다.
- `GameOverLine`의 Transform y가 실제 판정 높이입니다. 이미지 중앙을 원하는 제한 높이에 맞춥니다.
- Sorting Order 예시: DropGuide=-1, GameOverLine=2, Body=5, Face=6.

## 3. 평가와 통과 기준 제안

아래 점수는 게임 안에서 얻는 점수와 별개인 **과제 평가 점수**입니다.

| 구분 | 총점 | 통과 기준 제안 |
| --- | ---: | --- |
| 최종과제 | 100점 | 기본 항목 합계 70점 이상 |
| 대체과제 | 130점 | 기본 항목과 추가 항목 합계 100점 이상, 추가 항목에서 10점 이상 |

모든 기능을 구현해야 통과하는 방식이 아닙니다. 구현한 평가 항목의 점수를 합산합니다. 대체과제는 최종과제와 같은 기본 항목에 추가 기능을 더하며, 추가 항목도 모두 구현할 필요는 없습니다. 예를 들어 기본 90점 + 추가 10점, 또는 기본 80점 + 추가 20점이면 대체과제 통과 기준에 도달합니다.

컴파일되고 플레이 씬을 실행할 수 있는 상태로 제출하세요. 평가는 실제 게임을 플레이한 영상으로 진행합니다.

| 번호 | 기본 평가 항목 | 배점 |
| --- | --- | ---: |
| 1 | 플레이 화면과 바구니 동작 | 10점 |
| 2 | 과일 5종 표시와 물리 동작 | 10점 |
| 3 | 과일 접촉에 따른 표정 전환 | 10점 |
| 4 | 키보드 이동과 과일 낙하 | 15점 |
| 5 | 다음 과일 선택과 UI | 10점 |
| 6 | 같은 과일 합체 | 20점 |
| 7 | 점수 연결 | 10점 |
| 8 | 게임오버와 재시작 | 15점 |
| | **기본 항목 합계** | **100점** |

## 4. 공통 평가 항목 — 최종과제·대체과제 모두 해당

**공통 기능은 제출한 플레이 영상에서 확인되는 동작으로 채점합니다.** 코드 화면, Hierarchy, Inspector, Animator 창을 보여줄 필요는 없습니다. 프리팹 상속 구조·컴포넌트 연결·메서드 호출 여부 자체에는 점수를 부여하지 않습니다. 앞의 템플릿과 구성 안내는 구현을 위한 안내입니다.

각 평가 항목의 동작이 보이는 실제 플레이 장면을 제출하세요. 코드나 Inspector 조작으로 과일을 미리 배치한 별도 시연 장면은 사용하지 않습니다. 입력은 자막 또는 음성으로 설명하고, 시간 조건을 확인하는 장면은 정상 속도로 보여주세요. 장면을 나누어 제출할 수 있지만, 연쇄 합체·점수 변화·게임오버·재시작의 전후 흐름은 끊기지 않게 촬영합니다.

배점은 아래 큰 기능 단위로만 부여합니다. 기능 설명의 각 문장은 별도 점수 항목이 아닌 해당 기능의 동작 조건입니다.

### 1) 플레이 화면과 바구니 동작 — 10점

바구니, 낙하 위치 안내선, 게임오버 제한선, 현재·최고 점수, 다음 과일 UI가 잘리지 않고 보이게 구성합니다. 화면 배치와 색·장식은 자유입니다.

과일은 바구니의 좌우 벽과 바닥을 통과하지 않고 안쪽에 쌓여야 합니다. 좌우 가장자리에서 과일을 떨어뜨리는 장면과 과일이 바닥·다른 과일 위에 쌓이는 장면을 보여주세요. 그림의 경계와 실제 과일이 멈추는 위치가 자연스럽게 맞아야 합니다.

### 2) 과일 5종 표시와 물리 동작 — 10점

체리·귤·사과·멜론·수박이 서로 구분되는 몸통과 표정으로 표시되어야 합니다. 체리에서 수박으로 갈수록 크기가 커지고, 표정은 각 몸통에 자연스럽게 배치합니다.

과일은 아래로 떨어져 다른 물체와 닿으면 멈추거나 굴러갑니다. 몸통에서 눈에 띄게 떨어진 거리에서 공중에 걸리거나, 다른 과일에 깊게 겹친 채 멈추지 않아야 합니다. 멜론과 수박은 실제 플레이에서 합체해 보여주세요.

### 3) 과일 접촉에 따른 표정 전환 — 10점

공중에 있거나 벽·바닥에만 닿은 과일은 기본 표정입니다. 다른 과일과 닿으면 `>.<` 표정으로 바뀌고, 모든 과일 접촉이 사라지면 기본 표정으로 돌아옵니다. 여러 과일 중 하나와 떨어져도 다른 과일과 계속 닿아 있으면 접촉 표정을 유지합니다.

즉시 합체하지 않는 서로 다른 종류의 과일로 접촉 전후 모습을 보여주세요.

### 4) 키보드 이동과 과일 낙하 — 15점

←/→ 또는 A/D를 누르고 있는 동안 낙하 위치가 좌우로 움직이고, 키를 놓으면 멈춥니다. 양쪽 방향을 동시에 누르면 이동하지 않으며, 이동 중 낙하 높이는 유지합니다. 낙하 위치는 바구니 안으로 제한하고 가이드가 함께 움직이게 합니다.

Space를 누른 순간 해당 위치에서 과일 하나가 떨어집니다. 키를 길게 누르고 있어도 반복 생성하지 않습니다. 빠르게 여러 번 눌러도 기본 0.4초의 낙하 간격을 지켜야 합니다. 좌우 이동·가장자리 제한·길게 누르기·빠른 반복 입력을 영상에서 보여주세요.

### 5) 다음 과일 선택과 UI — 10점

무작위 낙하 후보는 체리·귤·사과입니다. 시작할 때 다음 과일이 표시되고, 낙하가 성공할 때마다 다시 선택합니다. 같은 과일이 연속 선택되어도 됩니다. 멜론과 수박은 직접 낙하하지 않습니다.

다음 과일 이미지와 이름이 선택에 맞게 함께 갱신되고, 표시된 과일과 실제 떨어지는 과일이 일치해야 합니다. 여러 번 낙하해 세 후보가 등장하는 모습을 보여주세요. 난수 코드나 확률의 균등함 자체는 영상 채점 대상이 아닙니다.

가장자리에서 작은 과일 다음에 큰 과일이 선택되어도 벽과 겹치거나 바구니 밖에서 생성되지 않아야 합니다.

### 6) 같은 과일 합체 — 20점

같은 과일 두 개가 닿으면 두 과일이 사라지고 중간 위치에 다음 단계 하나가 생깁니다. 체리 두 개→귤, 귤 두 개→사과, 사과 두 개→멜론, 멜론 두 개→수박의 네 단계를 보여주세요. 다른 종류끼리 또는 벽·바닥과 닿아서는 합체하지 않습니다. 수박 두 개는 닿아도 추가 합체하지 않습니다.

합체 결과가 중복 생성되거나 같은 원본이 두 번 사용되지 않아야 합니다. 같은 과일 세 개가 동시에 접촉하면 다음 단계 하나와 원래 단계 하나가 남아야 합니다.

합체 결과로 생긴 과일은 약 0.2초 대기 후 다시 합체합니다. 예를 들어 체리 합체로 생긴 귤이 기존 귤과 계속 닿으면 잠시 후 사과가 됩니다. 대기가 끝나기 전에 떨어졌다면 합체하지 않습니다. 일반 낙하 과일에는 이 생성 대기를 적용하지 않습니다.

합체 직후에도 결과 과일은 자연스럽게 낙하하거나 굴러야 합니다. 갑자기 공중에 고정되거나 엉뚱한 위치로 튀면 안 됩니다. 평균 속도 계산식 자체는 영상 채점 대상이 아닙니다.

### 7) 점수 연결 — 10점

단순 낙하에는 점수를 주지 않고 실제 합체 결과에 따라 아래 게임 점수를 누적합니다. 아래 숫자는 과제 배점이 아닌 게임 안의 보상입니다.

| 생성된 합체 결과 | 게임 내 획득 점수 |
| --- | ---: |
| 귤 | 10점 |
| 사과 | 30점 |
| 멜론 | 80점 |
| 수박 | 200점 |

합체 한 번당 보상을 한 번만 더하고, 합체 없이 접촉을 유지하는 동안에는 추가하지 않습니다. 체리 두 개가 귤이 되고 그 귤이 기존 귤과 합쳐지면 총 40점을 얻습니다. 영상에서 합체 전후 점수 변화를 읽을 수 있게 보여주세요.

현재·최고 점수가 플레이 결과와 일치하고 게임오버 패널에는 최종 점수가 표시되어야 합니다. R 재시작 시 현재 점수는 0으로 돌아가고, 같은 실행 중 최고 점수는 유지합니다. 실행 종료 후 기록 저장은 요구하지 않습니다.

### 8) 게임오버와 재시작 — 15점

새 과일은 생성 후 1초 동안 판정을 유예합니다. 이후 과일 윗면이 제한선 위에 1초 연속 남으면 게임오버입니다. 생성 직후 선 위를 잠깐 지나가거나, 잠시 넘었다 아래로 내려오면 게임이 계속되어야 합니다. 과일 윗면과 제한선이 함께 보이게 촬영하세요.

게임오버 시 결과 패널을 표시하고 과일의 물리 움직임을 멈춥니다. 가이드는 숨기며 좌우·Space를 눌러도 이동하거나 생성되지 않아야 합니다.

게임오버 상태에서 R을 누르면 기존 과일이 모두 사라지고, 결과 패널이 숨으며 가이드와 낙하 위치가 시작 상태로 돌아옵니다. 진행 중 R을 눌러도 판이 초기화되지 않아야 합니다. 재시작 후 이동·낙하·합체가 다시 동작하고 두 번째 판에서도 게임오버와 재시작이 가능해야 합니다. 점수 동작은 7번에서 평가합니다.

## 5. 대체과제 전용 추가 평가 항목 — 최대 30점

이 절은 **대체과제에만 해당**합니다. 최종과제의 총점과 통과 판정에는 포함하지 않습니다. 추가 항목은 과일 미리보기 10점과 리더보드 20점입니다. 세부 배점과 통과 기준은 검토용 초안입니다. 대체과제에서는 공통 항목 100점과 추가 항목 30점을 합쳐 총 130점으로 채점하며, 기본 기능 점수를 이 항목에서 다시 주지 않습니다.

### A) 다음 과일을 낙하 위치에 미리보기 — 10점

기본 다음 과일 UI와 별개로, DropPoint 위치에 떨어질 과일의 모습을 미리 보여줍니다.

- 선택된 과일과 같은 몸통 이미지·크기를 표시합니다.
- 좌우 이동과 무작위 선택 변경을 따라 미리보기가 갱신됩니다.
- 미리보기는 물리 충돌·합체·점수·게임오버 판정에 참여하지 않으며, 게임오버 시 숨고 재시작 시 복원됩니다.

### B) 리더보드 — 20점

각 판의 최종 점수를 모아 높은 점수순으로 보여주는 로컬 리더보드를 만듭니다. 한 번의 최고 점수만 보여주는 기본 UI와 별도로 여러 판의 기록을 비교할 수 있어야 합니다. 이번 초안의 범위는 같은 실행 안에서 유지되는 기록이며, 파일·PlayerPrefs 저장이나 온라인 서버 연결은 요구하지 않습니다.

- **기록 등록**: 게임오버가 확정될 때 해당 판의 최종 점수를 한 번만 등록합니다. 결과 패널을 다시 열거나 R을 반복 입력해도 같은 판이 중복 등록되지 않아야 합니다. 점수가 같은 서로 다른 판은 각각 별도 기록으로 인정합니다.
- **순위 정렬**: 점수 내림차순으로 정렬해 상위 5개 기록을 유지합니다. 동점이면 먼저 등록된 기록을 앞에 둡니다. 예를 들어 30점, 80점, 10점 순으로 종료했다면 목록에는 80점, 30점, 10점 순서로 표시합니다. 여섯 번째 기록이 생기면 정렬 후 상위 5개만 남깁니다.
- **리더보드 UI**: 게임오버 화면에서 각 기록의 순위와 점수를 TMP로 표시합니다. 기록이 5개 미만이면 실제 기록만 표시하고, 첫 판 이전에는 빈 상태를 자연스럽게 표시합니다. 기록이 갱신되면 화면도 갱신되어야 합니다.
- **재시작과 기록 유지**: 재시작하면 현재 점수만 초기화하고 기존 순위 기록은 유지합니다. 다음 판 종료 시 새 기록을 추가하며, 리더보드를 표시하는 동안 시간 정지와 R 재시작이 정상 동작해야 합니다. 게임 실행을 종료한 뒤까지 기록을 유지할 필요는 없습니다.
